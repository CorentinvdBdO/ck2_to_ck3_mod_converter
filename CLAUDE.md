# CK2 → CK3 mod converter — agent guide

Read `STATUS.md` first (state). This file: invariants, commands, pointers. Charter: `docs/PROJECT.md`. House rules: `~/.claude/CLAUDE.md`.

## What this repo is
- Python 3.12 + uv. Converts a CK2 total-conversion mod (test subject: Faerûn, cloned in `Faerun/`, gitignored) into a loadable CK3 1.19 mod.
- Output mod lives in `../claudespace/mods/faerun_ck2_to_ck3_converted` (own git repo, generated, never hand-edited). Submod: `../claudespace/mods/forgotten_kings`. Assets: `../ck3_fantasy_assets`.
- CK3 game files: `../claudespace/game_files` (symlink, read-only). CK3 workspace tooling (push to launcher, error.log, checks): `../claudespace`.

## Commands

- `uv run scripts/survey_terrain_history.py` — the CK2 `history/provinces` `terrain = X` tallies and what the bitmap says under each (`docs/evidence/terrain_history_survey.md`). `PYTHONPATH=$PWD/src uv run python scripts/measure_terrain_history_effect.py [--images]` — two real `map` runs, with and without the override, into `docs/evidence/terrain_history_effect.md`.
- `uv run scripts/survey_ck2_titles.py` — CK2 title-side tallies (every count quoted in `docs/step_titles.md`).
- `uv run scripts/tiger_titles_check.py` — ck3-tiger over the titles/history output, per diagnostic class and owning lane (writes `docs/evidence/tiger_titles.txt`).
- `uv run scripts/build_loc_key_renames_titles.py` — regenerate `mappings/loc_key_renames_titles.csv` (the hand-off to lane `loc`).

- `uv run scripts/build_loc_key_map.py [--check]` — merge every `mappings/loc_key_renames_*.csv` into `overrides/loc_keys.csv`, which the `loc` step reads as `[loc] key_map`. `--check` is in `ci/checks.sh`.
- Regenerate + validate the whole mod in five commands: `docs/integration_run.md`.
- `uv run scripts/collect_ck2_modifier_keys.py` → `uv run scripts/build_modifiers_csv.py` → `uv run scripts/classify_faerun_traits.py` → `uv run scripts/verify_ck3_keys.py` — regenerate the mapping tables in `mappings/` and verify every CK3 key against the 1.19 install (must report `MISSES: 0`).

- `uv run scripts/seed_culture_traditions.py` → `uv run scripts/verify_culture_traditions.py` — regenerate `overrides/traditions_of_culture_group.csv` (placeholder traditions per culture group) and check every id against the 1.19 install (must report `MISSES: 0, DLC-ONLY: 0`).
- `uv run scripts/survey_vanilla_bookmark_positions.py` / `uv run scripts/check_bookmark_positions.py <mod dir>` — the measured vanilla bookmark canvas, and a validation of a generated `fae_bookmarks.txt` (inside the canvas, no `{ 0 0 }`, no pair under the repulsion floor).
- `uv run scripts/check_trait_key_coverage.py` — every CK2 trait key in neither `mappings/` trait table, all at once (the converter raises on the first).
- `uv run scripts/check_locator_frame.py` — derive the `gfx/map/map_object_data` coordinate frame from vanilla (writes `docs/evidence/locator_frame.md`). `--mod <out dir> [--against <CK3 generated/ dir>]` validates a generated mod's locators: every instance **inside its own province** (concave-centroid ids excepted), and the per-type distance to `buildings` next to vanilla's own. `uv run scripts/measure_vanilla_locator_offsets.py` regenerates `mappings/locator_offsets.csv`; `uv run scripts/check_ck2_locator_slots.py` measures all seven CK2 slots against the generated map; `uv run scripts/locator_move_report.py --old DIR --new DIR` diffs two builds' locator sets (exit 1 if an id was lost).
- `uv run scripts/measure_vanilla_tree_mix.py` → `uv run scripts/build_tree_mix_csv.py` — measure vanilla's own P(tree mesh | terrain, climate, latitude band) over all 549,126 instances and regenerate `mappings/tree_mix.csv` (`docs/evidence/vanilla_tree_mix.csv`, `vanilla_tree_mix_conditioning.csv`, `vanilla_tree_patch_scale.csv`). `uv run --with matplotlib python scripts/report_tree_mix.py --before DIR --after DIR` — latitude-band × species tables and figure, ours vs vanilla (`docs/evidence/tree_mix/`).
- `uv run scripts/preview_dds.py <in.dds> <out.png> [--max-side N]` — decode a DXT1 DDS (the flat map) to a viewable PNG.
- `uv run scripts/pdx_scan.py [mod_dir] [--roundtrip N]` — parse every script file of a mod, report failures and timings.
- `uv run scripts/bisect_strip_custom_loc.py <mod dir> [--restore]` — bisection only: neutralise every `Custom('X')` call in a generated mod's localisation, to test whether unresolvable custom-loc calls are what kills a game load.
- `uv run scripts/survey_faerun_loc.py` → `docs/evidence/loc_quirks.md`; `uv run scripts/collect_ck2_loc_codes.py` → `docs/evidence/ck2_loc_codes.csv` (text-code coverage); `uv run scripts/check_ck3_loc.py <mod>` — validate a generated `localization/` tree (exit 1 on a malformed line).
- `nohup uv run scripts/build_ck3_vanilla_loc_keys.py > docs/evidence/ck3_vanilla_loc_keys.log 2>&1 &` — refresh the 169,096-key vanilla CK3 loc key cache.
- `uv run pytest -m "not slow"` — fast tests only (the slow ones parse the whole Faerûn clone).
- `uv run scripts/tc_scan_vanilla_refs.py [--atlantis DIR]` → `docs/evidence/tc_template_folders.csv` — which vanilla folders name vanilla titles/provinces/characters, and what ATL/EK2/GH do with each. `uv run scripts/tc_error_log_classes.py <error.log> [--mod DIR]` — the game log by class, and how much of the `title_links` class a generated mod already shadows. `uv run scripts/tc_check_shadow_callers.py <mod dir>` — **must report 0**: a blanked vanilla definition that a kept vanilla file still calls. `uv run scripts/tc_events_naming_titles.py --mod <dir>` — the events-lane hand-off. `scripts/tc_tiger_before_after.sh <scratch>` — ck3-tiger with and without the `tc_template` step.
- `uv run scripts/survey_cultures_religions.py` → `uv run scripts/seed_culture_overrides.py` → `uv run scripts/export_opinion_modifier_map.py` → `uv run scripts/check_id_collisions.py` → `uv run scripts/validate_cultures_religions.py` — the `cultures`/`religions` pipeline: source survey, first draft of `overrides/*.csv`, tables for the traits + loc lanes, vanilla-id safety, ck3-tiger evidence.

## Rules
- Base branch is `main`. Lanes `lane/<name>`. Never commit on main.
- Converter never invents content. No CK3 equivalent → emit a comment next to the nearest construct. Human input → `overrides/*.csv`, read by the converter.
- Every reader/writer gets a pytest with a fixture snippet. Parser changes need a round-trip test (parse → write → parse equal, comments kept).
- CK2 input encoding is Windows-1252; CK3 output is UTF-8 **with a BOM, decided by path not by content**: `pdx.encoding.encoding_for(rel)` gives one to everything under `common/`, `events/`, `history/`, `localization/`, `gfx/`, `tests/` and `map_data/geographical_regions/`, and none to the flat `map_data` files or `descriptor.mod`. `ctx.write_script`/`write_text` apply it; a literal leading `U+FEFF` in the text is consumed rather than written twice.
- Facts about CK2/CK3 formats go to `docs/` in the same commit (`docs/formats_*.md`), with file:line evidence from `Faerun/` or `game_files/`.
- Long runs (full conversion, image work > 2 min) under nohup with a log in `docs/evidence/`.

## Invariants (bite once, write here)
- CK3 1.19 vanilla map is 9216×4608, heightmap 16-bit at 2×. Custom dims allowed, any multiple of 64 (`assumed`); Elder Kings 2 8256×5504 and Godherja 8192×4096 both ship a **1×** heightmap, so 2× is a vanilla choice, not a rule. Ours: 8320×6784 — painted-extent crop plus a 128 px sea margin (`docs/map_scale.md` §7; `sea_margin_px = 64` gives the older 8192×6656).
- `positions.txt` is optional and **dead**: the string does not occur once in the 1.19 binary (`strings ck3.exe | grep -c positions.txt` → 0), and `default.map` comments it out in vanilla and both major TCs. What actually places holdings, CoAs, unit stacks, sieges and activity icons is `gfx/map/map_object_data/*_locators.txt`.
- **A custom province set must override all seven `gfx/map/map_object_data` locator files** (`building` `special_building` `siege` `activities` `player_stack` `other_stack` `combat`). The engine only fills *gaps* (`gameobjectlocators.cpp:126` "locator is incomplete", writes replacements to `Documents/…/Crusader Kings III/generated/`); an id vanilla also defines silently keeps **vanilla's European coordinate** — 3179 of Faerûn's 3694 holdings drew a median **3040 px** from their own land. `position` is `{ x y z }` in provinces.png pixels with **z bottom-up** (`z = height − y`); the placement is the province colour centroid (the engine's own answer, 1.6 px median). Written by `ck2ck3.map.locators`; evidence `docs/evidence/map_ui_research.md`, `scripts/check_locator_frame.py`.
- **The camera bound is `NCamera.PANNING_WIDTH` / `PANNING_HEIGHT`** — there is no `MAX_ZOOM` and no `MAP_BOUNDS`. Vanilla ships 9090/4696, so on a taller sheet the north is unreachable (2088 px of our 6784). Set both to the canvas, like Elder Kings 2, and move `START_LOOK_AT` with them (`ck2ck3.map.bootstrap.render_camera_defines` → `common/defines/graphic/<prefix>_graphics.txt`).
- The **3D map table** is not a mesh to author: four `object={}` entries per style in `gfx/map/map_object_data/map_table_<style>.txt`, `transform="x y z qx qy qz qw sx sy sz"` in the locator pixel frame, vanilla scale 5. Neither TC rescales it, and a sheet much taller than 4608 px overhangs it (`ck2ck3.map.table` re-centres and scales by `max(w/9216, h/4608)`).
- The zoomed-out **paper map is `gfx/map/terrain/flat_maps/flatmap.dds`, exactly canvas-sized DXT1**. Ship none and the game stretches vanilla's real-world Earth over your continent. All three reference maps ship one; mips are optional (vanilla has none). `ck2ck3.map.flatmap` + `ck2ck3.map.dxt1` write it.
- `map_data/default.map` loads the heightmap via `topology = "heightmap.heightmap"`, which points at `packed_heightmap.png` + `indirection_heightmap.png`. **`heightmap.png` alone is not what the game reads.** The converter writes the packed pair itself (`ck2ck3.map.packed_heightmap`, format in `docs/formats_packed_heightmap.md`); no map editor needed.
- Any custom map size needs a `common/defines` override: `WORLD_EXTENTS_X` = width−1, `WORLD_EXTENTS_Z` = height−1. The 16-bit water level is `WATERLEVEL / WORLD_EXTENTS_Y * 65535` (we write 3.8/51 → 4883). Get this wrong and the coastline moves silently.
- `replace_path` is **not** recursive: `history` does nothing for `history/provinces`. `map_data` needs none at all (same-filename override is enough). See `docs/output_bootstrap.md`.
- All three shipped CK3 heightmap/atlas PNGs are stored **bottom-up**.
- Faerûn has **67 culture groups / 419 cultures** and **15 religion groups / 94 religions** (`verified`; the survey's "~495 cultures" and "~130–184 religions" were upper bounds).
- A CK2 culture *group* carries only `graphical_cultures` and `alternate_start` — **no colour**. A CK3 language pillar requires one.
- CK3 1.19 has **no `tradition_caste_system` and no `tradition_druidism`** (`verified` 2026-09-08 against `game/common/culture/traditions/*.txt`); the real ids are `tradition_ruling_caste` and `tradition_sacred_groves`. A culture takes at most `DEFAULT_MAX_TRADITIONS = 5` (`common/defines/00_defines.txt:1163`). Verify every tradition id with `scripts/verify_culture_traditions.py`; never guess one from its English name.
- `common/culture/pillars`, `common/culture/traditions`, `common/ethnicities` and `common/modifier_definition_formats` are **not** `replace_path`s: an id emitted there must not collide with vanilla (Faerûn's `gur` and `mari` cultures do).
- ck3-tiger wants a **UTF-8 BOM on every script file under `common/` or `history/`, pure ASCII or not** (`verified` 2026-09-08: 98 generated ASCII files drew `warning(encoding)`). Vanilla agrees everywhere except `history/titles` (56 of 183) and `history/provinces` (91 of 177), which ship BOM-less ASCII files — laxity in two folders, not a rule. All 18 `game/tests/*.txt` have one and 17 are ASCII.
- Faerûn defines 15,356 baronies but builds 3857 holdings at 1357; barony set = built holdings, never the defined list. 3694 become CK3 provinces, 163 are demoted to comments (`docs/step_map_baronies.md`).
- `map_data/definition.csv` column 5 of a barony row **is** the CK3 barony title id `b_<ck2 name>` — the contract lane `titles-history` reads province ids from. Other rows keep the uppercase CK2 province slug.
- **CK2 gameplay terrain is the province-history `terrain = X` override first, the `terrain.bmp` majority second.** The bitmap is only CK2's fallback. 1040 of Faerûn's 2125 province files carry the line and 716 disagree with their own pixels, so ignoring it shipped the wrong terrain for a quarter of our baronies (farmlands 16 → 335). `[map] province_terrain_history`, table `mappings/terrain_history_overrides.csv`, rule and counts in `docs/step_map_terrain.md`. Paint stays per-pixel and does **not** follow the override.
- CK2 `history/provinces` `b_x = ct_something` builds a *building*, not a holding: resolving a holding type must skip any value that is not one of the nine CK2 holding types, or the barony vanishes.
- CK2 `positions.txt` is per **province**, and a CK2 province is a CK3 **county**, so exactly one barony per county — the **county capital** — has a CK2 coordinate; every other barony keeps the province colour centroid. Importable, and imported: slot 0 = capital/city (`verified`, CK2's binary names it) as the barony **seed** (`[map] ck2_position_seeds`) and as the county capital's **locator anchor** (`[map] ck2_locator_positions`, 99.6 % of 2116 capitals pass the inside-own-pixels gate); slot 4 = port, the non-capital `city_holding`'s seed. **Not** importable: slots 1/2/3/5/6 have no CK2-given meaning — slot 3 equals slot 0 in 58.1 % of Faerûn's blocks, and slot 1 sits 22.5 canvas px from slot 0, 3× vanilla's own unit-stack offset. `docs/step_map_assets.md`.
- **A CK3 locator type is placed relative to the settlement, not independently.** Over all 11,297 vanilla land ids every type sits within ~15 px of that province's `buildings` instance (`siege` 10.0, unit stacks 7.1/7.7, `combat` 13.6, `special_building` 9.1) — a siege marker is the army besieging the settlement. So the converter places **one anchor per province** and adds vanilla's own measured median offset per type (`mappings/locator_offsets.csv`, `scripts/measure_vanilla_locator_offsets.py`). Caveat: vanilla's offsets are a ring, so the median *vector* is ~1/3 of the median *distance* for the rotationally symmetric types (`[map] locator_offset_mode = "median_radius"` switches).
- **Every lane worktree gets its own venv (`uv sync --group dev` inside `wt/<lane>`), never a symlink to another checkout's.** A shared venv's editable `.pth` names ONE source tree, so `uv run ck2ck3` in any other worktree silently converts with another lane's code while `pytest` (`pythonpath = ["src", "."]`) stays green. Prove it once per worktree: `.venv/bin/python -c "import ck2ck3; print(ck2ck3.__file__)"` must print that worktree's `src` (`docs/integration_run.md`).
- CK3 localisation has no `FROM` scope; CK2 `From…` codes need a saved scope (`docs/loc_codes.md`).
- CK3 text formats are named in `game/gui/preload/textformatting.gui`; there is no `#Y`, yellow is `#M`.
- The PyPI package `jomini` is unrelated to Paradox parsing (battle simulator). Do not add it.
- **`common/bookmark_portraits` must not be empty.** A bookmark character with no file there crashes CK3 (ck3-tiger `fatal(crash)`, "This causes a crash in CK3 1.13"). Write a placeholder named after the character's `name` value.
- **`ck3-tiger` reads the `.mod` file you pass it, not `descriptor.mod`** — without the `replace_path` lines in that file every replaced vanilla file loads and you get thousands of phantom "redefined" diagnostics. `--game` wants the install dir, not its `game/` subfolder.
- CK3 `history/titles` allows **no top-level keys**; `liege` must be a strictly higher tier and must have a **living** holder at that date or the line is ignored.
- CK2 `landed_titles` `capital` is a **province id**, not a title. The province→county link is `title = c_x` inside the province-history file.
- **Any id two steps derive independently belongs in `ck2ck3.ids`.** Both halves look internally consistent, so the failure only shows up in ck3-tiger or the game: `titles` writing `name_list_sun_elf` while `cultures` writes `name_list_fae_sun_elf` was 2848 `error(missing-item)`, and `bookmarks` writing `fae_dyn_7743` while `dynasties` writes `fae_7743` was another 80.
- The **known-trait set** the `characters` port filters by is `mappings/trait_ck2_to_ck3.csv` — the `traits` step's own output — never a re-derivation from `vanilla_traits.csv` + `faerun_custom_traits.csv`, which miss the 38 traits deduped by exact CK3 id match and the 29 `approx`/`none` ones ported as new (8308 wrongly commented `trait` lines).
- **Vanilla CK2 content CK3 removed is replaced, not dropped.** `mappings/vanilla_traits.csv` `status` is an *action*: `exact` (83) dedupes, `approx` (16) ports the CK2 trait **and** records the CK3 near-equivalent, `none` (13) ports. So `mappings/trait_id_map.csv` is no longer a pure rename table — an `approx` row means **both** traits exist and applying it as a rename deletes the ported one (`ck2ck3.port.tables` skips them).
- A `mappings/*.csv` may open with a `#` comment block; **every** reader must skip comment lines. `vanilla_traits.csv` documents its status policy that way and broke three plain `csv.DictReader` call sites.
- CK3 1.19 has **no `set_dynasty` effect** (`set_house = dynasty_house:<id>` is the runtime form, and CK2 has no cadet houses to mint one from), **no same-gender marriage** (`add_spouse` between two of one gender is `error(wrong-gender)` and ignored), and `change_first_name` takes a **localisation key**, never a literal name. `add_spouse`/`remove_spouse`/`add_concubine` are dated-**history** keys; as effects they are `marry`/`divorce`/`make_concubine`, each taking a `character:<id>` scope.
- `replace_path = "tests"` is **mandatory** for a total conversion: vanilla's 18 `tests/*.txt` hard-code 1066 ids (character `122`, `k_croatia`) and fail en masse otherwise.
- A **bare script token that does not start with a letter breaks the CK3 parser, and it does not recover**: everything after it in the file is lost. Faerûn's `modron` names are serial numbers (`2BD71SF2`), and one of them cost the 14 `name_list_*` blocks that followed it in `fae_monsters.txt` — then an `EXCEPTION_ACCESS_VIOLATION` in `characterhistory.cpp`, because a character of one of those 14 cultures had no name list (`verified` 2026-09-08, `docs/evidence/game_load_2026-09-08.md`).
- A CK3 **name-list entry is a localisation key, not a display string** (`male_names = { Akarakay … }` + ` Akarakay:0 "Akarakay"`), and **a localisation key must be ASCII**: 0 of vanilla's 55,948 name keys hold a non-ASCII byte, and vanilla spells Björn `BjO_rn`, Åke `A__ke`. Letters, digits, `_`, `-` and `'` pass. `ck2ck3.nametokens` does the fold; the literals go to `localization/<lang>/<prefix>_names_l_<lang>.yml`.
- CK3 accepts exactly four localisation escapes — `\n` (47,430 uses in vanilla english), `\t` (224), `\"` (97), `\\` (5). Anything else is `localization_reader.cpp:111: Illegal localization break character` and **truncates the string**.
- CK3 wants **three** localisation keys per culture: `<id>`, `<id>_prefix`, `<id>_collective_noun` (vanilla `localization/english/culture/cultures_l_english.yml:460-462`, all three "Norse"). CK2 supplies only the first.
- `replace_path = "map_data/geographical_regions"` deletes **all 592** vanilla regions, and vanilla scripts, GUI and achievements name them. Every vanilla region name must be re-declared (empty is fine, `generate_modifiers = yes` kept for the 8 that have it — vanilla traits reference the `<region>_development_growth_factor` they mint), and the **seven `graphical_*` regions must exist and cover every land province** or every vanilla building asset's `graphical_regions` filter fails and every province logs "has no visual geographical region assigned". A null from one of these killed the frontend one second after the main menu (`dlc_fp1_region_core_mainland_scandinavia`).
- CK3 rejects a region that reaches one duchy or province through **two** sub-regions (`geographical_region.cpp: Region 'X' have multiple entries for the province 'N'`). CK2 tolerates it — `yehimal_region` shares 8 duchies with `tabot_region` and friends — so such a parent has to be emitted flat.
- A CK3 name list **must** carry `dynasty_names` (`MINIMUM_DYNASTY_NAMES = 2`, `common/defines/00_defines.txt:1145`; the define's own comment says culture-**group** names count toward it). CK2 keeps dynasty names globally in `common/dynasties` with a `culture` each, so step `dynasties` runs before `cultures` and hands them over — with none, all 419 name lists drew `culture_name_lists.cpp:169` and CK3 had no name to mint a generated character's dynasty from.
- `Setting idler 'Frontend'` in `debug.log` is the **main menu**; `Setting idler 'In Game'` needs the game to actually start a bookmark, which headlessly means the `-test` launch argument (`../claudespace/scripts/ck3_launch.sh … --args "-test"`). Without it a run waiting for `In Game` can only time out. **Vanilla with `-test` reaches `In Game` in 54 s** in this harness (`verified` 2026-09-08), so that is the control: a mod that does not is the mod's fault, not the harness's.

- **The heightmap de-terrace Gaussian (σ = 1.6 px) does not flatten real cliffs; the spectral fill is what is wrong.** Measured over Thay's 33 counties (`verified` 2026-09-10, `docs/report_map_paint.md` §7.1): on the steepest edges it keeps 67 % of the one-pixel step and **98 % of the drop over 34 km** — it costs sharpness, not amplitude. The fill, however, is 1.4–1.7× rougher than vanilla's most rugged coast in the 9.5–38 km band, and it sinks **8.19 % of all land onto the `water_level + 1` clamp floor** (2,166,924 px, median 76 px from any water, mean 3485 levels destroyed — `docs/evidence/report_map_paint/clamp_floor.csv`). An erosion lane wants a frequency-dependent gain, not a smaller sigma.
- **Our terrain paint is a strict two-material blend; vanilla's is 3.47.** Over land, ours uses 20 of vanilla's 101 materials, exactly 2.000 non-zero `detail_intensity` channels per pixel against vanilla's 3.467, blend entropy 0.73 bits against 1.49, primary weight 0.71 against 0.52 (`verified`, `docs/evidence/report_map_paint/paint_blend.csv`). 56.1 % of vanilla's own coverage is regional `gen_*`/`medi_*`/`northern_*`/`india_*`/`central_*` families `mappings/terrain_paint.csv` excludes by design.

- **`ck3-tiger` never validates vanilla's own files, only the mod's.** The 12,877 `title_links.cpp` "Failed to fetch a valid landed title" errors a total conversion causes are invisible to it: a full run with and without the `tc_template` step reports the same 56 errors (`verified` 2026-09-08, `scripts/tc_tiger_before_after.sh`). For that class the game's `error.log` is the only instrument.
- **An empty script block is not neutral.** An empty `scripted_trigger` body evaluates **true** in CK3, so blanking a vanilla trigger unlocks whatever it gated; a neutralised trigger needs `{ always = no }` and a neutralised `script_value` a bare `0` (`src/ck2ck3/tcshadow.py`).
- **Blanking a vanilla file deletes the definitions in it, and a vanilla file you keep may still call one.** The first draft of `tc_template` orphaned 534 definitions (accolade character templates ← `00_accolades_scripted_effects.txt`, Japanese succession triggers ← `common/laws/00_succession_laws.txt`). Keep the keys and drop the bodies instead; `scripts/tc_check_shadow_callers.py` must report 0.
- **Override-by-filename deletes a vanilla database as well as `replace_path` does**, and both shipped 1.19 total conversions rely on it: Elder Kings 2 ships 149 stub-sized files at vanilla paths and Godherja 137, EK2's nine `tests/` overrides included. Use a shadow for pure deletion; keep `replace_path` for a folder we fill (`docs/tc_template.md`).
- Vanilla has a **`h_` title tier above empire** (`h_china`, `h_india`, `h_roman_empire`, `h_dar_al_islam`, `h_eastern_roman_empire`): a `[ekdcb]_` regex misses 997 of the 12,877 dangling-title references. Read the id set out of `common/landed_titles` instead of matching a shape.
- Every one of vanilla's **536 `events/*.txt` carries a UTF-8 BOM** and ck3-tiger wants one there too, so `events/` is in `pdx.encoding.BOM_PREFIXES`.
- **A CK3 event id's number must fit in 16 bits.** ck3-tiger accepts every generated id up to `43308` and flags every one from `70000` up with `warning(event-namespace): Event names should be in the form NAMESPACE.NUMBER` (`verified` 2026-09-10 over 1704 ids, `docs/evidence/tiger_events_2026-09-10_summary.txt`); vanilla's own highest number is **9999** over all 536 event files, so nothing there pins the bound closer. `ck2ck3.ids.MAX_EVENT_NUMBER` re-allocates the 79 Faerûn ids above it, per namespace, counting down from the ceiling — never hand-build `<ns>.<ck2 number>`.
- **`sender` is a required field of a CK3 `letter_event`, `hidden = yes` or not** (41 × `error(field-missing)` on hidden ones). A `character_event` needs none, and a **hidden** event needs no `option` at all (`game/events/misc_events.txt:3` is exactly `hidden` + `trigger` + `immediate`). CK3 has four event types (`character_event` `letter_event` `court_event` `activity_event`) and defaults to the first; CK2's `is_triggered_only` **is** that default and has no CK3 field (`game/events/_events.info:12-36`).
- **`orphan = yes` stops CK3 logging an event as unreferenced** (`game/events/_events.info:242`; vanilla uses it in 8 files, e.g. `game/events/witch_events.txt:1049`). Every ported-but-inert event wants it, because nothing fires it yet.
- **CK2's `event_target:x = { ... }` is CK3's `scope:x = { ... }`** (`verified`, `game/events/witch_events.txt:56`) — but a CK3 saved scope **dies with its event**, while a CK2 event target is stored on the character and survives. So an event that reads `scope:x` without its own `save_scope_as = x` is broken at runtime, and CK3 has no `FROM` at all: both are hard live-gates in `ck2ck3.steps.events` (`unsaved_scope`, `from_scope`).
- CK2's gated text converts one-to-one: `desc = { text = K trigger = { … } }` → `desc = { first_valid = { triggered_desc = { trigger = { … } desc = K } } }`, and an option's `name = { text = K trigger = { … } }` is **already** valid CK3 (`game/events/_events.info` "Dynamic Description Appendix" §3 and "Option name specifics"). Event window art is `theme = <id>` from `common/event_themes/00_event_themes.txt` (191 ids installed), never a picture path.

- `history/province_mapping` must never be empty when `history/provinces` has any block: the 1.19 loader crashes (null deref) on an empty table. `history_titles` writes one entry (`docs/DECISIONS.md` 2026-09-08). A `replace_path` that leaves a folder empty is only safe when the engine tolerates an empty table; test with a game launch, not just ck3-tiger.
