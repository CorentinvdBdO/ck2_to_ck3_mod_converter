# Decisions (append-only; date, decision, reason)

- 2026-09-07 — Converter stays in Python 3.12 (uv), no Rust rewrite. Reason: Rust toolchain absent on the dev machine, team fluency, PIL/numpy/scipy cover the image work; revisit only if parsing speed on 16k-file mods becomes a blocker.
- 2026-09-07 — Three repos: converter, generated mod (`faerun_ck2_to_ck3_converted`, never hand-edited), submod (`forgotten_kings`), plus an asset library. Reason: upstream Faerun CK2 mod is still updated; a clean regenerate must stay possible.
- 2026-09-07 — Target CK3 1.19.x; vanilla map is 9216×4608 (not 8192×4096 as the old `convert.py` assumed). Map dimensions become a converter parameter.
- 2026-09-07 — Canon political map: Atlas of Ice and Fire "Nations of the Forgotten Realms" (1371 DR). Reference image kept locally in `refs/` (gitignored, copyrighted).
- 2026-09-07 — Anything without a CK3 equivalent is emitted as a comment next to the nearest CK3 construct. No invention in the converter.
- 2026-09-07 — Human-judgement inputs (barony seeds, race→asset mapping, id remaps) are override files read by the converter, so a re-run after an upstream update keeps human work.
- 2026-09-07 — Race model: heritage pillar `species_<race>` parameter + genetic `creature_*` traits (ported from CK2) + on-birth inheritance table + tiered portraits (trait morphs → placeholder ethnicity → asset pack). Reason: Elder Kings 2 pattern is the only proven CK3 race system; no reusable 3D assets exist, so placeholders are unavoidable (`docs/design_races.md`).
- 2026-09-07 — Asset library accepts only packs with an explicit licence or written permission. Reason: every surveyed fantasy mod reserves all rights; Faerûn CK2 portraits are 2D and not portable anyway.
- 2026-09-07 — ck3-tiger v1.19.0 installed at `~/.local/bin/ck3-tiger` (from github.com/amtep/tiger). Converter output will be validated with it in `ci/checks.sh` once a mod exists.
- 2026-09-07 — Vanilla-trait dedupe policy for step `traits`: a CK2 trait that CK3 already has is **never redefined**. `mappings/vanilla_traits.csv` `exact`/`approx` rows and any other Faerûn trait whose id CK3 1.19 `common/traits/00_traits.txt` declares verbatim become a rename row in `mappings/trait_id_map.csv` (143 of 1417) for the characters/events/loc lanes; `none` rows are ported as new traits. Reason: redefining a vanilla trait silently replaces vanilla behaviour, and an identical trait id on both sides is the only machine-checkable evidence available. Ported trait ids keep their CK2 name so `has_trait` in ported script and the localisation key rename both resolve (`docs/step_traits.md`).
- 2026-09-07 — Map bootstrap layer is generated by the converter from the installed vanilla 1.19 tree, not vendored from Atlantis: `replace_path` for `common/landed_titles`, `history/{characters,cultures,province_mapping,provinces,struggles,titles,wars}` and `map_data/geographical_regions`, plus throwaway one-barony-per-province titles and province history. Reason: Atlantis is unlicensed, targets 1.16.*, two of its neutralisation paths no longer exist in 1.19, it covers 1 of vanilla's 11 landed_titles files, and it cannot boot as cloned (`docs/output_bootstrap.md`).
- 2026-09-07 — Map scale is derived, not chosen: `factor = faerun_km_per_px / vanilla_km_per_px = 2.90 / 1.4839 = 1.9543`, canvas 8192×6656, heightmap 1×. Vanilla's 1.4839 km/px is the core-Europe latitude fit (R² 0.9962), deliberately not the whole-map 1.7426, because the CK3 sheet is not a uniform projection and Europe is the density the game was tuned against. Reason: the legacy 5918/4096 = 1.4448 was unmeasured and 26% too small (`docs/map_scale.md`).
- 2026-09-07 — `common/defines` must override `WORLD_EXTENTS_X` = width−1 and `WORLD_EXTENTS_Z` = height−1 for any custom map size, with `WORLD_EXTENTS_Y = 51` / `WATERLEVEL = 3.8` (the Elder Kings 2 and Godherja values, giving a 16-bit water level of 4883). Reason: without it the coastline silently moves; verified in vanilla, EK2 and Godherja defines (`docs/map_scale.md` §3).
- 2026-09-07 — Localisation keys keep their CK2 name (`c_x`, `c_x_adj`, `EVTDESC…`, trait and religion keys). Reason: every other lane generates identifiers straight from CK2 names, so text resolves with no rename table; unknown leftover keys are harmless, and `[loc] key_map` (a `ck2_key,ck3_key` CSV, applied last) exists for the lane that does need a rename. Vanilla CK3 collisions (827 on Faerûn) are kept by default: a total conversion replaces the interface too.
- 2026-09-07 — CK2 `From`/`FromFrom` in localisation become the CK3 saved scopes `ck2_from`/`ck2_fromfrom`. Reason: CK3 event text has no `FROM` scope (0 uses in `game/localization/english`) and 30 % of Faerûn's text codes are `From…`; the converted events must `save_scope_as` those names. Text with no CK3 equivalent at all is wrapped in a visible `<!CK2:…!>` marker and counted, never invented (`docs/loc_codes.md`).
- 2026-09-07 — Religions: one CK3 religion **family per CK2 religion group** and one **faith per CK2 religion**, so family/religion stay 1:1. Reason: CK3 has a level above religion that CK2 lacks; a mechanical 1:1 fill needs no design and gives every group its own hostility slot.
- 2026-09-07 — Cultures: one **heritage + one language pillar per CK2 culture group**, one culture per CK2 culture. Reason: the CK2 group is both the race tag and the shared-tongue unit (`docs/design_races.md` item 1); 67 groups → 67 heritages / 67 languages, 419 cultures → 419 cultures + 419 name lists.
- 2026-09-07 — Default core tenets `tenet_ritual_celebrations` / `tenet_sanctity_of_nature` / `tenet_ancestor_worship` (`assumed`; CK2 has no tenet concept), overridable per faith in `overrides/faith_tenets.csv`. A CK2 flag beats a default (`pacifist` → `tenet_pacifism`, `allow_looting` → `tenet_warmonger`, …) because it is data, not a guess.
- 2026-09-07 — All DLC is assumed present, but a DLC-gated construct must stay switchable: the governments step gets an `[governments] assume_dlc` flag with the fallbacks in `mappings/government_map.csv`. Reason: the dev machine has every DLC, players may not.
- 2026-09-07 — Generated string ids carry the `fae_` prefix wherever CK3 allows one (`heritage_fae_*`, `language_fae_*`, `name_list_fae_*`, `rf_fae_*`, `fae_*_religion`, `fae_hs_*`, `fae_placeholder_*`), while ids living in a `replace_path` folder keep their CK2 name (cultures, faiths) so localisation keys stay on CK2 names. Reason: additive folders must not collide with vanilla; replaced folders cannot.
- 2026-09-07 — CK2 `<culture_group>_opinion` fans out to one `<culture>_opinion` per culture of the group. Reason: `verified` CK3 1.19 has no culture-group opinion scope (0 `heritage_*_opinion` keys), so the single CK2 line has no single CK3 target.
- 2026-09-07 — The converter writes **no `common/culture/traditions`**: Faerûn's `default_culture_modifier` is empty (403 of 406 users) and the other two culture modifiers cover 3 cultures, all emitted as comments. Reason: a generated tradition with no content to carry would be invention.
- 2026-09-07 — Character and dynasty ids become the strings `fae_<ck2_id>`. Reason: CK3 accepts string ids (33104 of 71124 vanilla history ids are non-numeric, Elder Kings 2 uses them for all 16515 of its characters) and vanilla numeric ids reach 1000230517, so no numeric range is safe to squat; the prefix makes a collision with vanilla or the Atlantis placeholders impossible.
- 2026-09-07 — CK2 `dna` and `properties` are dropped with a comment. Reason: they are indices into CK2's 11-character 2D portrait sprite atlas; CK3 `dna` references a `common/dna_data` gene template and accessories come from `gfx/portraits/portrait_modifiers`. Nothing translates (`docs/design_races.md` item 6).
- 2026-09-07 — CK2 `race` is carried by the `creature_*` traits only, never by a separate field. Reason: `docs/design_races.md` item 3; the traits are the mechanic.
- 2026-09-07 — Dynasty names get generated loc keys `dynn_fae_<id>` and the `dynasties` step writes `localization/english/fae_dynasties_l_english.yml` itself. Reason: CK2 stores the name as a literal inside `common/dynasties`, CK3 stores a loc key, and no other lane reads that folder — so the literal would be lost otherwise. Rename rows for the `loc` lane: `mappings/loc_key_renames_characters.csv`.
- 2026-09-07 — Any mechanically minted CK3 localisation key must be checked for MURMUR3A collisions against the vanilla key set, not just chosen. Reason: CK3 keys localisation by MurmurHash3 x86_32 and a collision silently drops one entry; 11951 generated `dynn_fae_<id>` keys hit two vanilla keys on the first run (`dynn_fae_109`/`Burnon`, `dynn_fae_1215`/`b_tradruk`). Implementation: `ck2ck3.port.loc_hash` (`docs/formats_characters.md` §8).
- 2026-09-07 — CK2 `effect_even_if_dead` is ported as a plain `effect` block plus a comment. Reason: the key does not exist anywhere in the CK3 1.19 install (0 occurrences); Faerûn uses it 407 times and dropping those blocks would lose real content.
- 2026-09-07 — Unmappable CK2 death reasons fall back to the nearest generic CK3 reason (unknown → `death_natural_causes`) with the CK2 value kept in a comment. Reason: only 8 of the 80 reasons Faerûn uses exist in CK3; inventing CK3 death reasons is out per the no-invention rule, and dropping the `death_reason` key loses the cause of death entirely.
