# Decisions (append-only; date, decision, reason)

- 2026-09-07 — Converter stays in Python 3.12 (uv), no Rust rewrite. Reason: Rust toolchain absent on the dev machine, team fluency, PIL/numpy/scipy cover the image work; revisit only if parsing speed on 16k-file mods becomes a blocker.
- 2026-09-07 — Three repos: converter, generated mod (`faerun_ck2_to_ck3_converted`, never hand-edited), submod (`forgotten_kings`), plus an asset library. Reason: upstream Faerun CK2 mod is still updated; a clean regenerate must stay possible.
- 2026-09-07 — Target CK3 1.19.x; vanilla map is 9216×4608 (not 8192×4096 as the old `convert.py` assumed). Map dimensions become a converter parameter.
- 2026-09-07 — Canon political map: Atlas of Ice and Fire "Nations of the Forgotten Realms" (1371 DR). Reference image kept locally in `refs/` (gitignored, copyrighted).
- 2026-09-07 — Anything without a CK3 equivalent is emitted as a comment next to the nearest CK3 construct. No invention in the converter.
- 2026-09-07 — Human-judgement inputs (barony seeds, race→asset mapping, id remaps) are override files read by the converter, so a re-run after an upstream update keeps human work.
- 2026-09-07 — Race model: heritage pillar `species_<race>` parameter + genetic `creature_*` traits (ported from CK2) + on-birth inheritance table + tiered portraits (trait morphs → placeholder ethnicity → asset pack). Reason: Elder Kings 2 pattern is the only proven CK3 race system; no reusable 3D assets exist, so placeholders are unavoidable (`docs/design_races.md`).
- 2026-09-07 — Asset library accepts only packs with an explicit licence or written permission. Reason: every surveyed fantasy mod reserves all rights; Faerûn CK2 portraits are 2D and not portable anyway.
- 2026-09-07 — ck3-tiger v1.19.0 installed at `~/.local/bin/ck3-tiger` (from github.com/amtep/tiger). Converter output will be validated with it in `ci/checks.sh` once a mod exists.
- 2026-09-07 — Vanilla-trait dedupe policy for step `traits`: a CK2 trait that CK3 already has is **never redefined**. `mappings/vanilla_traits.csv` `exact`/`approx` rows and any other Faerûn trait whose id CK3 1.19 `common/traits/00_traits.txt` declares verbatim become a rename row in `mappings/trait_id_map.csv` (143 of 1417) for the characters/events/loc lanes; `none` rows are ported as new traits. Reason: redefining a vanilla trait silently replaces vanilla behaviour, and an identical trait id on both sides is the only machine-checkable evidence available. Ported trait ids keep their CK2 name so `has_trait` in ported script and the localisation key rename both resolve (`docs/step_traits.md`).
- 2026-09-07 — Map bootstrap layer is generated by the converter from the installed vanilla 1.19 tree, not vendored from Atlantis: `replace_path` for `common/landed_titles`, `history/{characters,cultures,province_mapping,provinces,struggles,titles,wars}` and `map_data/geographical_regions`, plus throwaway one-barony-per-province titles and province history. Reason: Atlantis is unlicensed, targets 1.16.*, two of its neutralisation paths no longer exist in 1.19, it covers 1 of vanilla's 11 landed_titles files, and it cannot boot as cloned (`docs/output_bootstrap.md`).
- 2026-09-07 — Map scale is derived, not chosen: `factor = faerun_km_per_px / vanilla_km_per_px = 2.90 / 1.4839 = 1.9543`, canvas 8192×6656, heightmap 1×. Vanilla's 1.4839 km/px is the core-Europe latitude fit (R² 0.9962), deliberately not the whole-map 1.7426, because the CK3 sheet is not a uniform projection and Europe is the density the game was tuned against. Reason: the legacy 5918/4096 = 1.4448 was unmeasured and 26% too small (`docs/map_scale.md`).
- 2026-09-07 — `common/defines` must override `WORLD_EXTENTS_X` = width−1 and `WORLD_EXTENTS_Z` = height−1 for any custom map size, with `WORLD_EXTENTS_Y = 51` / `WATERLEVEL = 3.8` (the Elder Kings 2 and Godherja values, giving a 16-bit water level of 4883). Reason: without it the coastline silently moves; verified in vanilla, EK2 and Godherja defines (`docs/map_scale.md` §3).
- 2026-09-07 — Localisation keys keep their CK2 name (`c_x`, `c_x_adj`, `EVTDESC…`, trait and religion keys). Reason: every other lane generates identifiers straight from CK2 names, so text resolves with no rename table; unknown leftover keys are harmless, and `[loc] key_map` (a `ck2_key,ck3_key` CSV, applied last) exists for the lane that does need a rename. Vanilla CK3 collisions (827 on Faerûn) are kept by default: a total conversion replaces the interface too.
- 2026-09-07 — CK2 `From`/`FromFrom` in localisation become the CK3 saved scopes `ck2_from`/`ck2_fromfrom`. Reason: CK3 event text has no `FROM` scope (0 uses in `game/localization/english`) and 30 % of Faerûn's text codes are `From…`; the converted events must `save_scope_as` those names. Text with no CK3 equivalent at all is wrapped in a visible `<!CK2:…!>` marker and counted, never invented (`docs/loc_codes.md`).
- 2026-09-07 — Religions: one CK3 religion **family per CK2 religion group** and one **faith per CK2 religion**, so family/religion stay 1:1. Reason: CK3 has a level above religion that CK2 lacks; a mechanical 1:1 fill needs no design and gives every group its own hostility slot.
- 2026-09-07 — Cultures: one **heritage + one language pillar per CK2 culture group**, one culture per CK2 culture. Reason: the CK2 group is both the race tag and the shared-tongue unit (`docs/design_races.md` item 1); 67 groups → 67 heritages / 67 languages, 419 cultures → 419 cultures + 419 name lists.
- 2026-09-07 — Default core tenets `tenet_ritual_celebrations` / `tenet_sanctity_of_nature` / `tenet_ancestor_worship` (`assumed`; CK2 has no tenet concept), overridable per faith in `overrides/faith_tenets.csv`. A CK2 flag beats a default (`pacifist` → `tenet_pacifism`, `allow_looting` → `tenet_warmonger`, …) because it is data, not a guess.
- 2026-09-07 — All DLC is assumed present, but a DLC-gated construct must stay switchable: the governments step gets an `[governments] assume_dlc` flag with the fallbacks in `mappings/government_map.csv`. Reason: the dev machine has every DLC, players may not.
- 2026-09-07 — Generated string ids carry the `fae_` prefix wherever CK3 allows one (`heritage_fae_*`, `language_fae_*`, `name_list_fae_*`, `rf_fae_*`, `fae_*_religion`, `fae_hs_*`, `fae_placeholder_*`), while ids living in a `replace_path` folder keep their CK2 name (cultures, faiths) so localisation keys stay on CK2 names. Reason: additive folders must not collide with vanilla; replaced folders cannot.
- 2026-09-07 — CK2 `<culture_group>_opinion` fans out to one `<culture>_opinion` per culture of the group. Reason: `verified` CK3 1.19 has no culture-group opinion scope (0 `heritage_*_opinion` keys), so the single CK2 line has no single CK3 target.
- 2026-09-07 — The converter writes **no `common/culture/traditions`**: Faerûn's `default_culture_modifier` is empty (403 of 406 users) and the other two culture modifiers cover 3 cultures, all emitted as comments. Reason: a generated tradition with no content to carry would be invention.
- 2026-09-07 — Character and dynasty ids become the strings `fae_<ck2_id>`. Reason: CK3 accepts string ids (33104 of 71124 vanilla history ids are non-numeric, Elder Kings 2 uses them for all 16515 of its characters) and vanilla numeric ids reach 1000230517, so no numeric range is safe to squat; the prefix makes a collision with vanilla or the Atlantis placeholders impossible.
- 2026-09-07 — CK2 `dna` and `properties` are dropped with a comment. Reason: they are indices into CK2's 11-character 2D portrait sprite atlas; CK3 `dna` references a `common/dna_data` gene template and accessories come from `gfx/portraits/portrait_modifiers`. Nothing translates (`docs/design_races.md` item 6).
- 2026-09-07 — CK2 `race` is carried by the `creature_*` traits only, never by a separate field. Reason: `docs/design_races.md` item 3; the traits are the mechanic.
- 2026-09-07 — Dynasty names get generated loc keys `dynn_fae_<id>` and the `dynasties` step writes `localization/english/fae_dynasties_l_english.yml` itself. Reason: CK2 stores the name as a literal inside `common/dynasties`, CK3 stores a loc key, and no other lane reads that folder — so the literal would be lost otherwise. Rename rows for the `loc` lane: `mappings/loc_key_renames_characters.csv`.
- 2026-09-07 — Any mechanically minted CK3 localisation key must be checked for MURMUR3A collisions against the vanilla key set, not just chosen. Reason: CK3 keys localisation by MurmurHash3 x86_32 and a collision silently drops one entry; 11951 generated `dynn_fae_<id>` keys hit two vanilla keys on the first run (`dynn_fae_109`/`Burnon`, `dynn_fae_1215`/`b_tradruk`). Implementation: `ck2ck3.port.loc_hash` (`docs/formats_characters.md` §8).
- 2026-09-07 — CK2 `effect_even_if_dead` is ported as a plain `effect` block plus a comment. Reason: the key does not exist anywhere in the CK3 1.19 install (0 occurrences); Faerûn uses it 407 times and dropping those blocks would lose real content.
- 2026-09-07 — Unmappable CK2 death reasons fall back to the nearest generic CK3 reason (unknown → `death_natural_causes`) with the CK2 value kept in a comment. Reason: only 8 of the 80 reasons Faerûn uses exist in CK3; inventing CK3 death reasons is out per the no-invention rule, and dropping the `death_reason` key loses the cause of death entirely.
- 2026-09-07 — Vanilla scale reference stays the **core-Europe 1.4839 km/px** figure, not the whole-map 1.7426. Reason: gameplay density (barony count, army travel) lives in core Europe, and the Europe latitude fit is the tightest available (R² 0.9962); the CK3 sheet is not a uniform projection so no single scalar is "the" scale (`docs/map_scale.md` §1).
- 2026-09-07 — The canvas is **cropped to the painted CK2 extent plus a 128 px sea margin**, rounded up to a multiple of 64 (`[map.provinces] crop_to_painted`, `[map] sea_margin_px`). Reason: unpainted source border is dead weight in every output file. **Measured consequence for Faerûn: the crop is a no-op** — the painted extent *is* the whole 4096×3328 bitmap, and the mod's 21 % of unassigned white pixels are interior ocean between painted sea provinces, not a border. So the decision only widens the margin, taking the canvas from 8192×6656 to **8320×6784** (+3.4 % pixels) without shrinking the padding ocean. The pass is kept because it is correct and costs one boolean reduction; `sea_margin_px = 64` restores the old canvas in one line. Open for the coordinator (`docs/map_scale.md` §7).
- 2026-09-07 — Physical baronies are the CK2 holdings **built** in `history/provinces` at `[mod] bookmark_date` ∪ anything built by the latest bookmark, placed by seeded geodesic Voronoi with a human override loop. 3857 holdings, 3694 placed, 163 demoted to comments in 128 counties. Reason: Faerûn defines 15,356 baronies but builds 3857; all-defined would give 8×8 px provinces and one-per-county would throw away the cities and temples that carry the economy (`docs/step_map_baronies.md`, `docs/design_map.md` §B).
- 2026-09-07 — `map_data/definition.csv` column 5 of a barony row is the **CK3 barony title id** (`b_<CK2 barony name>`), one row per barony province; sea/lake/river/impassable/county-less rows keep the uppercase CK2 province slug. Reason: it is the contract lane `titles-history` reads province ids from, and ck3-tiger reads the column as a localisation key, so the value has to be a key we emit anyway.
- 2026-09-07 — Barony province colours are `blake2b(barony_id)` truncated to 24 bits with a deterministic upward probe past taken colours, never Python's salted `hash()`. Reason: a hash keeps the `provinces.png` diff local when a barony is added upstream, and a per-process salt would make the output non-reproducible (`docs/design_map.md` §B.7).
- 2026-09-07 — River tributary warnings (248 of the 319 ck3-tiger river warnings) are **deferred to the backlog**, not fixed in the barony lane. Reason: they do not stop the map loading and the fix is a rivers-geometry problem, not a barony one (`docs/evidence/tiger_map_baronies.txt`).

- 2026-09-07 — Title ids keep their CK2 names (`e_`/`k_`/`d_`/`c_`/`b_`), and so do title localisation keys. Reason: 1408 CK2 script references and the whole CK2 localisation resolve for free; the only CK3-side difference is the adjective, which CK3 reads from `<title>_adj` and CK2 never wrote, so lane `loc` gets 5667 copy rows in `mappings/loc_key_renames_titles.csv` instead of a renaming scheme (`docs/step_titles.md`).
- 2026-09-07 — CK2 titular/organisation titles (the 317 in `titular_titles.txt`, the 156 mercenary companies, `e_rebels`, `e_pirates`, the offmap empire) become `landless = yes` titular CK3 titles with the vanilla landless recipe and a comment naming the source file. CK2 `republics.txt` patrician families are the exception: they are 161 **root-level baronies**, which CK3 forbids, so they are emitted commented out.
- 2026-09-07 — Coats of arms are placeholders derived from the title's CK2 `color` (`pattern_solid.dds` + `color1=rgb { r g b }`, the same recipe as vanilla's own `default` entry) in `common/coat_of_arms/coat_of_arms/fae_titles.txt`. The 3438 CK2 `gfx/flags/*.tga` are **not** converted: decomposing them into CK3 `pattern` + `colored_emblem` is its own lane, and the title→flag list is recorded in `docs/evidence/ck2_flags.csv`.
- 2026-09-07 — A CK2 title that cannot be a legal CK3 title is emitted as a **commented-out block**, never dropped: 11530 unbuilt baronies, 1461 demoted ones, 161 patrician families and 12 county subtrees. Reason: `province = <id>` is mandatory for a CK3 barony and a CK3 county needs at least one barony, and the submod must be able to promote any of them by deleting a `#`.
- 2026-09-07 — `common/bookmark_portraits` is **not** left empty (correcting `docs/mapping_world.md` gotcha 8): ck3-tiger reports `fatal(crash)` — "This causes a crash in CK3 1.13" — for a bookmark character with no file there. The converter writes a minimal placeholder per character, to be replaced by an in-game `dump_bookmark_portraits`.
- 2026-09-07 — `src/titles/` is deleted and the title/map models of `src/games/ck2/classes.py` are removed. Reason: `src/ck2ck3/titles/ck2read.py` and `src/ck2ck3/map/ck2read.py` replace both, and `docs/converter_code_assessment.md` flagged the duplication ("two divergent model hierarchies"). `Character`/`Culture`/`Religion*` stay in `classes.py` for lanes `characters` and `cultures-religions` to decide on.
- 2026-09-08 — CK3 script output always gets a UTF-8 BOM, decided by **path** (`ck2ck3.pdx.encoding.encoding_for`), not by whether the text is pure ASCII. Reason: ck3-tiger 1.19 reports `warning(encoding)` for a BOM-less ASCII file in any `common/`or `history/` database (98 generated files did), and vanilla puts one on every file in those databases except `history/titles` and `history/provinces` — laxity in two folders, not a rule. The flat `map_data` files and `descriptor.mod` keep plain UTF-8, which vanilla and all four installed workshop mods also do.
- 2026-09-08 — Any identifier two steps derive independently lives in `ck2ck3.ids`, never re-derived per step. Reason: both halves stay internally consistent, so the mismatch is invisible until ck3-tiger or the game — `titles` writing `name_list_sun_elf` against `cultures`' `name_list_fae_sun_elf` was 2848 `error(missing-item)`, and `bookmarks`' `fae_dyn_7743` against `dynasties`' `fae_7743` another 80 plus 77 `warning(bookmarks)`.
- 2026-09-08 — The known-trait set the `characters` port filters by is the `traits` step's own output (`ctx.data["traits"]`, else `mappings/trait_ck2_to_ck3.csv`), never a re-derivation from the classification tables. Reason: the tables miss the 38 traits the step dedupes by exact CK3 id match and the 7 `status = none` vanilla traits it ports as new, so 8308 `trait` lines were commented out of `history/characters` for traits the mod does declare.
- 2026-09-08 — The converter emits its own `tests/` file (step `tests`, last in the default order) by reading the generated mod back, and `replace_path = "tests"` is mandatory. Reason: a total conversion must replace vanilla's 18 test files, which hard-code 1066 ids; and an assertion derived from the mod's own output cannot claim something the mod does not say. Logic ported from `../claudespace/scripts/ck3_gen_tests.py` so it runs in the same pass and cannot go stale.
- 2026-09-08 — `[loc] key_map` rows carry a `mode`: `rename` drops the CK2 key, `copy` emits the text under both. Reason: the `traits` hand-off is a genuine rename (`brave` → `trait_brave`), while the `titles` and `religions` hand-offs are copies (CK3 needs `k_neverwinter` *and* `k_neverwinter_adj`), and treating the latter as renames would leave every title nameless.
- 2026-09-08 — CK2 same-gender marriages are reported, not rewritten. Reason: CK3 1.19 has no same-gender marriage (`add_spouse` between two of one gender is `error(wrong-gender)` and ignored); changing a gender or dropping a marriage the source asserts would both be invention. 8 pairs in Faerûn, in `docs/evidence/characters_integrity.csv`.
- 2026-09-08 — `common/defines` is **not** a `replace_path`: defines merge per key, so `fae_defines.txt` overrides only WORLD_EXTENTS/WATERLEVEL. Reason: replacing the folder drops all vanilla defines; EK2 and Godherja do not replace it either.
- 2026-09-08 — A `replace_path` is only allowed for a folder the converter actually writes. Reason: first game load crashed (access violation) while loading `frontend_loadingscreen.gui`; the descriptor replaced `gfx/interface/illustrations/loading_screens`, `gfx/portraits/portrait_modifiers` and `common/dna_data` with nothing.
- 2026-09-08 — A CK3 name-list entry is emitted as a **generated ASCII token**, never the CK2 literal, and the literal becomes that token's localisation. Reason: CK3 reads `male_names` entries as loc keys (77,736 `Missing loc X`), a loc key must be ASCII (251 `Invalid character in key name`), and a bare token starting with a digit breaks the script parser for the rest of the file — which cost 14 name lists and then crashed character-history loading. Vanilla does exactly this (`BjO_rn` + ` BjO_rn:0 "Björn"`).
- 2026-09-08 — The `map` step re-declares **every** vanilla `map_data/geographical_regions` name it does not otherwise define, empty, carrying `generate_modifiers` where vanilla has it. Reason: the folder is a `replace_path`, so all 592 vanilla regions vanish; a vanilla GUI lookup of one (`dlc_fp1_region_core_mainland_scandinavia`) returned a null and crashed the frontend one second after the main menu.
- 2026-09-08 — A land province's `graphical_*` region comes from its CK2 culture's `graphical_cultures` → `overrides/gfx_of_culture_group.csv` `building_gfx` → the vanilla region shipping that building set, defaulting to `graphical_western`. Reason: the assignment only chooses a building mesh, and the existing human table is the only place a CK2 graphical culture is already mapped to a CK3 one — no new override file, and the default matches the `cultures` step's own `western_*` fallback.
- 2026-09-08 — `[loc] custom_loc` defaults to `marker`: a CK2 customizable-localisation code becomes a visible `<!CK2:…!>`, not `Custom('name')`. Reason: `Custom()` needs the name to exist in `common/customizable_localization`, nothing emits that folder, and a call to a name CK3 does not know is an error per evaluation — 795 names over 4,068 lines, 34 of them the last log lines before an access violation in game setup. Text-code coverage drops 94.0 % → 91.0 % and comes back with `custom_loc = "call"` when the custom-loc port ships.
- 2026-09-08 — `[loc] named_scope` defaults to `marker`: a reference to a CK2 saved scope (an event target, the `ck2_from` a `From` code needs, or a CK2 chain word used as the head) becomes a visible `<!CK2:…!>` rather than a CK3 scope reference. Reason: only an event, decision or on_action that ran `save_scope_as` puts the scope there and nothing ports CK2's events yet; CK3 answers an unresolvable one with `pdx_data_localize.cpp: Data error in loc string '<key>'`, and one of those was the last log line before an access violation in game setup. 64,803 occurrences over 2,566 codes — the size of the event port's debt, reported as `named_scope_markered`.
- 2026-09-08 — Step `dynasties` runs **before** `cultures`, which fills each name list's `dynasty_names` from `ctx.data["dynasties"]["names_by_culture"]`, topping a culture up from its culture group when it has fewer than `MINIMUM_DYNASTY_NAMES`. Reason: CK2 keeps dynasty names globally in `common/dynasties` (each with a `culture`) while CK3 keeps them per name list; with none, the game logged `culture_name_lists.cpp:169 ... less than MINIMUM_DYNASTY_NAMES` for all 419 name lists and had no name to mint a generated character's dynasty from. The group top-up is vanilla's own rule (`common/defines/00_defines.txt:1145`).
- 2026-09-08 — `history/province_mapping` always gets one entry (two placed baronies of one county). Reason: **root cause of the game-setup crash**: ck3.exe 1.19.0.6 binary-searches the province-mapping table when loading any `history/provinces` block and dereferences a null begin pointer when the table is empty (crash @0x14207f7b1, 25 bisecting launches, `verified`). Godherja ships a single `6 = 20` for the same reason; Elder Kings 2 inherits vanilla's six files.
- 2026-09-08 — The bookmark at `[mod] bookmark_date` gets `test_default = yes`. Reason: `-test` (and `scripts/ck3_test.sh`) generates the game state from that bookmark; without it the state is built at date -1.1.1, no title holder applies and every bookmark character is unborn (first In Game run, 46/46 holder tests failed).
- 2026-09-08 — Every land province without a barony title (CK2 wasteland, any terrain) is listed in `impassable_mountains`. Reason: CK3 logs "Province N has no associated title … Game will probably crash" for each (210 on the first In Game run); terrain-based classification alone missed highlands, deserts and islets.
- 2026-09-08 — CK2 `immortal_age = N` becomes `add_trait = immortal` + `set_immortal_age = N` in one effect block. Reason: CK2 immortal_age implies immortality; CK3 rejects set_immortal_age on a non-immortal (1429 errors) and otherwise ages 3382 deities and ancients past 1000 years at 1357.
- 2026-09-08 — `employer = X` is emitted only while X holds a title on that date (hand-off `ctx.data["titles"]["landed"]` from `history_titles`); otherwise commented. Reason: **root cause of the game-setup crash at 1357**: CK3 logs "X is not landed and cannot be set as employer" and dies in powerful-vassal setup; removing every employer line reached In Game (166/173 tests passed).
- 2026-09-08 — A character who holds a title on or after an `employer` entry date loses that entry (commented). Reason: **root cause of the 1357 game-setup crash**: 62 employer lines on rulers at 1357 crashed powerful-vassal setup; removing exactly those reached In Game (166/173 generated tests pass). Over-drops a courtier who is landed only much later; documented in step_characters.
- 2026-09-08 — Generated bookmark tests compare `title:X = { holder = root }`, not `holder = this` (inside a title scope `this` is the title).
- 2026-09-08 — The blank total-conversion layer is a set of empty same-name **shadows** and key-only **stubs** generated from the installed vanilla 1.19 tree by step `tc_template`, driven by `mappings/tc_template.csv`; no new `replace_path`. Reason: override-by-filename deletes a vanilla database just as well (Elder Kings 2 ships 149 such files, Godherja 137), the repo rule keeps `replace_path` for folders we fill, and 12,877 `title_links` errors plus a crash on the Silk Road situation came from vanilla content naming vanilla titles. Content inside a mechanic database is neutralised rather than blanked, because blanking orphaned 534 definitions that files we keep still call (`docs/tc_template.md`).
