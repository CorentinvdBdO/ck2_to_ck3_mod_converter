## The one surprise: pinning the port seed regressed the demotion count

Goal A's spec (and `docs/map_fidelity.md` §2) frames the port slot as a
pinned coordinate, the same tier as `override`/`gazetteer`/`capital_position`.
Shipping it that way (first implementation) gave **205 demoted** — worse than
the 163 baseline the task explicitly forbids regressing past. Cause: a
farthest-point *sampled* seed gets Lloyd-relaxed toward its region's centroid
every growth pass, which is what keeps a small county's split balanced; a
pinned port coordinate does not, and a county whose port sits off-centre (a
real harbour position, not a sampling artifact) ends up lopsided and loses a
straggler in the regrow pass. Making `port_position` seeds relaxable (they
still start from the real slot-4 coordinate, they just get nudged toward
balance like a sampled seed) fixed it: 152 demoted, an **improvement** over
163. `capital_position`, `override` and `gazetteer` stay pinned — only the
port slot's own measured cost changed the call. Documented in
`docs/step_map_baronies.md` §4 and `configs/faerun.toml`.

## Unverified in game (the coordinator's call)

- Whether CK3 actually renders `detail_index.tga`/`detail_intensity.tga`
  correctly on a non-vanilla-sized canvas. Everything checkable without the
  game checked out: exact vanilla filenames/format (RGBA8, TGA image type 2 —
  **not** RLE, `verified` by reading the byte offsets of the real files),
  same size as `provinces.png`, origin bottom-left (`verified` by a PIL
  round-trip), ordinals matching `materials.settings` declaration order,
  intensities summing to 255 on every pixel (asserted in code), determinism.
  ck3-tiger raised nothing about them. Only an actual game load settles
  whether the map renders our terrain instead of Europe's.
- The ~452 MB size cost (two ~226 MB uncompressed files) — `docs/map_fidelity.md`
  §4.1 flagged this as needing a size-vs-quality human call; this lane shipped
  the conservative, vanilla-matching choice (full size, uncompressed) rather
  than gambling on RLE or a half-resolution pair, both of which were open
  questions this lane's own reading of the vanilla files partly settled (RLE:
  vanilla itself does not use it, so this lane does not either) and partly
  left open (smaller-than-`provinces.png` pairs: untested).
- The dithered blend is texture-space noise, not the ridged/structured detail
  vanilla's own paint edges have; `docs/map_fidelity.md` §4.1 already called
  this "a refinement, not a requirement" and it stays out of scope here.
- `[map] terrain_paint = false` / `skip_images = true` are the escape hatches
  if the ~452 MB is unacceptable for a first playtest; both were exercised in
  code review but not run end-to-end in this session (they use the same
  `if cfg.terrain_paint:` / `if not skip_images:` guards the rest of the step
  already relies on, so they are low-risk, just not separately timed).
