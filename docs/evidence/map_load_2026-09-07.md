`ck3_launch.sh` (owned by lane `fk-testing`) does the whole job: registers the
mod with `push_mod.sh`, enables it in `dlc_load.json` and restores the file
afterwards, resolves the Proton env and the display, refuses to start a second

Add `--marker ingame` to require a bookmark to actually start rather than just
the main menu, and `--keep` to leave the game running for a look at the map.

  there is no native Linux binary, so do not exec the binary directly;
* the live user directory is **inside the Proton prefix**, not

* launch arg `-test` auto-starts the default bookmark and runs `tests/*.txt`
  unattended; `-debug_mode` gives the console.

## What "the map loaded" looks like

In order of increasing confidence:

1. **`logs/debug.log` reaches `Setting idler 'Frontend'`** — the executable
   started, read the mod, and got to the main menu. A custom map that is
   malformed usually dies *before* this, during map load, so reaching the
   frontend already rules out the whole class of "provinces.png / heightmap /
   definition.csv is unreadable" failures.
2. **`logs/debug.log` reaches `Setting idler 'In Game'`** — a bookmark started,
   which means the title layer resolved against the province ids and the game
   built a playable world. This is the real bar for this lane.
3. **`logs/error.log` has no line mentioning `province`, `map_data`,
   `heightmap`, `definition` or our `fae_` prefix.** Read it with
   `scripts/ck3_errors.sh fae` from claudespace, which de-duplicates and sorts
   by frequency.
4. **The map renders at the right scale.** Eyeball it with `--keep`: the
   Sword Coast should span roughly the same screen distance as vanilla's
   Italy-to-Greece, because that is exactly what the scale factor was measured
   to guarantee (`docs/map_scale.md`).

`ck3_launch.sh` writes all of this to
`claudespace/docs/evidence/launch_faerun_ck2_to_ck3_converted_<date>.log`, with
a five-line summary at the end (marker reached, process alive, error counts).

## Failure modes to expect on the first real run, and where to look

| symptom | likely cause | where |
|---|---|---|
| dies during map load, no frontend | packed heightmap mismatch | `docs/formats_packed_heightmap.md`; re-run `scripts/decode_packed_heightmap.py` on our own `map_data` and compare against `heightmap.png` |
| coastline in the wrong place, land under water | `WORLD_EXTENTS_*` wrong | `common/defines/fae_defines.txt` must be width−1 / height−1; `docs/map_scale.md` §3 |
| black or missing provinces | a definition.csv colour owns no pixels | `docs/evidence/lost_provinces.csv` |
| "province X has no title" spam | the throwaway landed_titles missed a land province | `common/landed_titles/fae_landed_titles.txt` |
| rivers look broken | known: 319 tiger river warnings remain | `docs/evidence/tiger_2026-09-07.txt` |
